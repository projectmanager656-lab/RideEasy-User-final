# Communication & reporting preferences

- Wants concise end-of-task reports structured into explicit sections: routes/pages found, missing or broken items discovered, files modified, what was fixed, API/backend mismatches fixed, functionality that could not be verified without a live environment, exact validation commands used, and each command's final result. Confidence: 0.8
- Wants findings tied to exact identifiers — file paths, component/function names, line numbers, routes/triggers, and Git commit/branch attribution — so each claim can be located and verified precisely. Confidence: 0.8
- Appreciates explicitly flagging what could not be verified end-to-end (e.g. flows needing a real driver, socket pairing, SMS, or payment environment) rather than claiming full success. Confidence: 0.8
- Requests token-efficient execution and minimal output (e.g. appends "use min token" to a task spec); keep tool usage and final summaries concise while still covering the required report items. Confidence: 0.8
- Reports bugs and follow-ups tersely — quotes on-screen error messages verbatim (e.g. "Invalid credentials fix this login problem", or a whole observed sequence like "An account already exists with this email/phone. Please log in instead." then "Invalid credentials") with no symptoms, reproduction steps, or account details, and may paste the entire raw browser console dump including full stack traces and unrelated noise (network 401/409s, DevTools banners) for the agent to parse; expects the agent to trace, diagnose, and fix autonomously (e.g. digging through logs/DB when the identifier isn't supplied, or pinning a crash to stale Vite cache from the stack) rather than demanding more context. Confidence: 0.8
- Describes a visual bug in prose and says a screenshot is provided ("I have provided a screenshot of the current ride/history route display", "I have provided two screenshots showing…") but the image repeatedly fails to attach (same failure across many tasks); expects the agent to proceed from the written description plus the code (locating the right component and diagnosing the real defect itself, and stating which screen it inferred) rather than refusing to start — while still flagging that the screenshot never arrived. Confidence: 0.7
- Feature requests arrive in the same terse, typo-laden one-liner style (e.g. "convert remaning dark and light theme in remanig pages also languga converter apply all pages dont change other code") with scope left open (which app, which screens, which languages); expects the agent to audit the codebase first and settle only the genuinely ambiguous scope forks before executing. Confidence: 0.6
- An umbrella "fix everything" request (e.g. "solve all bug and apis fix this confidence 100 make") signals an exhaustive, comprehensive pass over ALL bugs and API mismatches to completion, not a single scoped patch; the user wants the agent to chase every integration gap, deliver at full (100%) confidence, and verify thoroughly even if it goes beyond a token-efficient pass. Confidence: 0.6
- Follows up on a just-completed task with a very short additive instruction that relies on the conversation context to say what it means (e.g. "also remove tap to speck option" right after the chat-header removal) — restating no page, component, or file, and leaving the previous uncommitted work in place; expects the agent to infer the target (the same page just edited) and apply the same strict, whole-feature treatment there. Confidence: 0.6
- Sometimes replaces the usual terse one-liner with an exhaustive, formally-structured "MASTER PROMPT" — numbered requirement sections, explicit MUST / DO-NOT rule lists (including a long list of screens/architecture that must remain untouched), an acceptance-criteria checklist of numbered end-to-end tests, and a mandated numbered final-report template (often closing with a "CODE REVIEW" section: run git status/git diff, review every changed file, revert unrelated edits, do not commit or push) — and expects every listed rule and acceptance criterion to be honored and each one verified. Confidence: 0.8
e: 0.75
